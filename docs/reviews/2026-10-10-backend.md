## Minor

### PATCH idempotent re-settle silently mutates provider_ref on settled op, index.ts:444-446

When an already-settled operation is PATCH'd with the same `settled_micro_usd` (idempotent path), a new `provider_ref` is still applied if it differs. This allows silent mutation of a finalized billing reference under the guise of an idempotent retry. If `provider_ref` is an immutable audit field, drop lines 444-446 and return 200 immediately. If mutable, document the intent.

### PATCH settle does not guard against non-active statuses, index.ts:438

The guard is `if (op.status === 'settled')`. If status is `cancelled` (or any other terminal state), the UPDATE at line 450 runs and transitions the operation to `settled`. This corrupts budget accounting for future reservations. Add: if `op.status` is not in `('reserved', 'uncertain')`, return 409 `invalid_state` before the UPDATE.
