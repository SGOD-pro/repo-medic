## Minor
### 🟡 Missing shutdown timeout fallback during process termination, `frontend/tests/browser_acceptance.mjs:527` [Resolved]
**Problem**: In step four of check nine, the test stops the backend process using SIGTERM and awaits process exit without a timeout fallback. If the backend process deadlocks or ignores the signal, the acceptance test promise will hang indefinitely.
**Why it matters**: A hanging test halts automated continuous integration pipelines and requires manual process cancellation.
**Suggested fix**: Add a timeout fallback that escalates to SIGKILL if the process does not terminate within three seconds, matching the pattern used in the test cleanup helper.
**Resolution**: Unified process termination in stopProcess helper with three second fallback escalating to SIGKILL.

### 🟡 Uncleared timer handle on normal process exit, `frontend/tests/browser_acceptance.mjs:434` [Resolved]
**Problem**: The test cleanup helper schedules a fallback timer to issue SIGKILL after three seconds. When the process exits normally before this timer fires, the exit listener resolves the promise but does not clear the timeout handle.
**Why it matters**: Active timers on the event loop keep the Node process alive unnecessarily until the timer expires.
**Suggested fix**: Store the timeout identifier and invoke clearTimeout inside the exit listener before resolving the promise.
**Resolution**: Added clearTimeout in the once exit listener inside stopProcess to ensure timers do not remain on the event loop.
