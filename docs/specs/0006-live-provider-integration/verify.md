# 0006. Live provider integration: Verification plan

This verification plan provides step by step instructions for verifying milestone K4 live provider integration.

## Offline verification (runs without external credentials)

1. Verify package dependencies and static analysis:
   ```bash
   cd backend
   uv run flake8 src tests scripts
   uv run mypy src scripts
   ```

2. Run offline unit and integration test suites:
   ```bash
   cd backend
   uv run pytest tests/engine/ -v
   uv run pytest tests/ -v
   ```

3. Run worker integration tests:
   ```bash
   cd db-worker
   node test_worker.mjs
   ```

4. Verify offline preflight fail closed detection for missing provider credentials:
   ```bash
   cd backend
   uv run python scripts/preflight_check.py --live-providers
   ```
   Assert that preflight fails closed when `NEBIUS_API_KEY` or `TOKEN_FACTORY_API_KEY` is not set.

## Operator live verification (requires live Nebius credentials)

1. Configure operator environment in `backend/.env`:
   ```bash
   REPOMEDIC_MODE=live
   TOKEN_FACTORY_API_KEY="your_token_factory_key"
   TOKEN_FACTORY_BASE_URL="https://api.tokenfactory.us-central1.nebius.com/v1/"
   TOKEN_FACTORY_MODEL="nvidia/nemotron-3-super-120b-a12b"
   NEBIUS_API_KEY="your_nebius_key"
   NEBIUS_PROJECT_ID="your_project_id"
   NEBIUS_SANDBOX_IMAGE="python:3.12-bookworm"
   ```

2. Run live preflight verification (validates credentials, contree SDK operations, spending limits, and public git repository access):
   ```bash
   cd backend
   uv run python ../scripts/preflight_check.py --live-providers --repository-url https://github.com/SGOD-pro/repo-medic.git --commit-sha 453a0b6c6b125177504cdd941902b8d48266ed1c
   ```
   Confirm that all provider endpoints, project scopes, spending caps, repository access, and SDK dependencies report passing status.

3. Run live provider smoke test:
   ```bash
   cd backend
   REPOMEDIC_RUN_LIVE_PROVIDERS=true uv run pytest tests/test_k4_live_e2e.py -k test_live_provider_smoke -v
   ```
   Confirms model prompt completion and sandbox python inspection pass independently without running a full repair pipeline.

4. Execute single live sequential repair acceptance run:
   ```bash
   cd backend
   REPOMEDIC_RUN_LIVE_PROVIDERS=true uv run pytest tests/test_k4_live_e2e.py -k test_live_provider_successful_repair_acceptance -v
   ```
   Or via the operator runner script:
   ```bash
   uv run python scripts/run_live_sequential_repair.py
   ```
   Confirm:
   - Baseline passes twice with identical test counts.
   - Upgrade reproduces expected failure (`AttributeError: 'Engine' object has no attribute 'execute'`).
   - Candidate patch is generated by Nemotron model.
   - Patch is verified in isolated ephemeral sandbox snapshot.
   - Run transitions to `succeeded` (a failed repair does not satisfy acceptance).
   - Durable artifacts (`patch.diff`, `verify.log`, `evidence.json`) are stored and downloaded.
   - Budget consumption is settled and stays under 2.00 USD.
   - Remote sandbox resources are cleaned up cleanly.
